# 标书智审 BidSmart — 风险登记册

## 技术风险

| ID | 风险 | 严重度 | 可能性 | 影响 | 缓解措施 |
|----|------|--------|--------|------|----------|
| T-01 | **单文件 SPA 可维护性** — index.html 2058 行，缺乏模块化，多人协作困难，功能越加越臃肿 | 中 | 高 | 代码难以维护，Bug 定位困难，新功能开发效率下降 | 短期：严格代码分区注释；中期：引入 Alpine.js 或拆分 JS 模块；长期：迁移至 Vue/React |
| T-02 | **SQLite 并发瓶颈** — 单文件数据库，写入串行化，高并发下性能急剧下降 | 高 | 中 | 多用户同时操作时审查超时、上传失败 | P2 迁移 PostgreSQL；过渡期：SQLite WAL 模式 + 写入队列 |
| T-03 | **模型依赖不可用** — DeepSeek API 或 BGE 模型 (HuggingFace) 不可访问 | 高 | 低 | 核心审查功能完全瘫痪 | DeepSeek: 配置备用 API endpoint + 本地模型降级方案；BGE: 模型文件本地缓存 + 首次部署预下载 |
| T-04 | **大文件处理 OOM** — 200MB+ PDF/DOCX 解析时内存溢出 | 中 | 中 | 审查任务失败，进程 OOM Kill | 流式解析 (pymupdf 支持)；文件大小硬限制；大文件分页审查 |
| T-05 | **向量检索精度退化** — numpy dot-product 在大规模文档下精度不足，响应变慢 | 低 | 低 | 知识库搜索结果质量下降 | P2 迁移 FAISS；监控检索延迟和用户反馈 |

## 安全风险

| ID | 风险 | 严重度 | 可能性 | 影响 | 缓解措施 |
|----|------|--------|--------|------|----------|
| S-01 | **JWT 密钥泄露** — HS256 secret 泄露导致任意用户伪造 | 严重 | 低 | 攻击者可冒充任意用户访问所有项目和文件 | 密钥通过 `.env` 管理，不入库；定期轮换；P2 升级 RS256 |
| S-02 | **DEK 丢失** — KEK/DEK 密钥文件损坏或丢失 | 严重 | 低 | 已加密文件永久不可解密 | 密钥备份策略；KEK 离线安全存储；加密文件多副本 |
| S-03 | **文件上传攻击** — 恶意文件上传 (zip bomb, 路径穿越) | 高 | 中 | 服务器资源耗尽或文件系统被破坏 | 文件类型白名单；大小限制；UUID 文件名防路径穿越；病毒扫描 (P3) |
| S-04 | **审计日志篡改** — 攻击者获取权限后删除审计记录 | 中 | 低 | 操作不可追溯，合规检查失败 | 审计日志追加写入 (append-only)；日志异地备份；P2 引入日志签名链 |

## 运维风险

| ID | 风险 | 严重度 | 可能性 | 影响 | 缓解措施 |
|----|------|--------|--------|------|----------|
| O-01 | **ECS 单点故障** — 单台 ECS 宕机导致服务完全不可用 | 高 | 低 | 所有用户无法访问系统 | systemd Restart=always 自动恢复；监控告警；P2 引入备用实例 + 健康检查切换 |
| O-02 | **备份策略缺失** — 无自动化备份，数据丢失不可恢复 | 严重 | 中 | 数据库损坏或误删导致项目数据永久丢失 | 定时 crontab SQLite dump + 文件 rsync；备份保留 30 天；定期恢复演练 |
| O-03 | **存储空间耗尽** — 大量文件上传导致磁盘满 | 中 | 中 | 新上传失败，数据库写入失败 | 磁盘使用率监控 (≥80% 告警)；文件生命周期策略 (P2)；存储配额 |
| O-04 | **依赖版本冲突** — Python 包升级导致兼容性问题 | 低 | 中 | 服务启动失败或运行时异常 | requirements.txt 固定版本；venv 隔离；升级前在 staging 环境验证 |
| O-05 | **安全组配置错误** — 端口意外暴露或误封 | 高 | 低 | 服务不可达或未授权访问 | 安全组变更审批；定期审计安全组规则；最小权限原则 (仅 39001) |
