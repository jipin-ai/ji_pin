# project-management-ux — 需求规格

## 功能需求

### FR-1: 项目创建（含元数据）
**EARS: Event-driven**
> 当用户点击"创建项目"时，系统应展示一个表单包含以下字段：项目名称（必填）、投标部门、投标书编辑人、投标时间。

**验收标准:**
- [ ] 表单包含 4 个字段：项目名称（必填）、投标部门（选填）、编辑人（选填）、投标时间（选填日期选择器）
- [ ] 项目名称非空校验，空则提示"请输入项目名称"
- [ ] 提交成功后，项目出现在项目列表中
- [ ] 提交失败时，错误信息展示在表单上方

### FR-2: 项目列表与导航
**EARS: Ubiquitous**
> 系统应展示所有项目的列表，包含项目名称、部门、文件数量和创建时间。

**验收标准:**
- [ ] 项目列表以卡片或表格形式展示
- [ ] 每个项目显示：名称、部门、文件数、创建时间
- [ ] 点击项目可进入项目详情/文件视图
- [ ] 空列表时展示"暂无项目，请创建第一个项目"

### FR-3: 项目上下文下的文件上传
**EARS: Event-driven**
> 当用户在某个项目下上传文件时，系统应将文件归属到该项目，并在上传完成后刷新该项目的文件列表。

**验收标准:**
- [ ] 进入项目后，上传区域默认关联当前项目（无需再选）
- [ ] 上传成功后，文件列表即时更新
- [ ] 文件列表显示：文件名、大小、上传时间
- [ ] 支持拖拽上传和点击上传

### FR-4: 文件审查 — 项目文件选择
**EARS: State-driven**
> 在文件审查页面，系统应从项目文件夹获取已上传的招标文件和投标文件供用户选择。

**验收标准:**
- [ ] 文件审查页有两个下拉框：选择招标文件、选择投标文件
- [ ] 下拉框列出所有项目的所有文件，按项目分组
- [ ] 或：先选项目 → 再选文件（联动）
- [ ] 两个文件都选中后，"开始审查"按钮启用
- [ ] 审查完成后，结果展示在页面中

### FR-5: 工作流引导
**EARS: State-driven**
> 在用户完成一个步骤后，系统应引导用户进入下一步操作。

**验收标准:**
- [ ] 上传文件完成后，显示"前往文件审查"入口
- [ ] 文件审查完成后，显示"查看详细结果"引导
- [ ] 没有文件的项目，显示"上传文件"引导

## 非功能需求

### NFR-1: 性能
- 文件列表加载时间 < 1s（10 个文件以内）
- 大文件上传进度可见（前端反馈，非精确进度条）

### NFR-2: 兼容性
- 支持 Chrome/Edge/Firefox 最新两个版本
- 支持 1920x1080 和 1366x768 分辨率

### NFR-3: 可用性
- 所有操作不超过 3 次点击
- 错误信息使用中文，描述具体问题

## 约束

- 前端技术：纯 HTML/CSS/JS，不引入框架
- 后端 API：RESTful，已部分实现（DB迁移、Schema、documents 列表API）
- 文件存储：本地文件系统，路径 `storage/{project_id}/`
- 暗色主题保持一致性

## 边界外（Out of Scope）

- 项目成员管理界面（ProjectMember 模型后端接入延期）
- 审查历史持久化（ReviewSession 接入延期）
- 文件在线预览（延期至 P2）
- 审查结果导出 PDF/Excel（延期至 P2）
- 移动端适配
