# project-management-ux — Discovery Brief

## 问题描述

用户反馈了 4 个 UX 问题，根源相同：**项目管理到文件审查的工作流断裂**。

### 用户反馈（原文）
1. 首页"文件上传"页面中的"选择项目"栏是什么意思？为什么要这个？他的作用是什么？
2. 我在"选择项目"栏选择想选择的项目，没有看到下一步？
3. "文件审查"页面中，我点击"选择招标文件"，里面没有看到可以选择的文件，已经上传的招标文件没有体现出来。同样"选择投标文件"也是一样。
4. 上传招标文件和投标文件前应该有项目名称，投标部门，投标书编辑人，投标时间等内容的输入框，建立文件夹，文件夹名称就是项目名称，然后上传的招标文件和投标文件存储在相应的文件夹内。"文件审查"是从项目文件夹内获取招标文件和投标文件。

### 根因分析
| # | 现象 | 根因 |
|---|------|------|
| 1 | 「选择项目」含义不清 | 缺少项目管理界面，概念未传达。当前只有一个 `<select>` 下拉框 |
| 2 | 选完项目没有下一步 | 选中项目后没有展示项目详情、已有文件、后续操作引导 |
| 3 | 文件审查下拉为空 | `GET /projects/{id}/documents` API 端点不存在（只有 POST 上传和 GET 下载） |
| 4 | 缺少项目元数据 | Project 模型原有只有 name+description。已添加 department/editor/bid_time 但前端未体现 |

## 期望结果

一个完整的工作流：

```
创建项目（名称+部门+编辑人+投标时间）
  → 项目文件夹自动创建
  → 上传招标文件 + 投标文件到该项目
  → 文件审查：从项目文件夹选文件
  → AI 管线审查
  → 查看结果
```

## 边界

**In scope:**
- 项目创建表单（含元数据字段）
- 项目列表/详情展示
- 项目下文件列表
- 文件审查页面的项目-文件选择联动
- 文件上传页面的项目上下文优化

**Out of scope:**
- 项目成员管理（ProjectMember 模型已有，暂不接入）
- 审查历史持久化
- 文件预览/对比视图
- 审查结果导出
